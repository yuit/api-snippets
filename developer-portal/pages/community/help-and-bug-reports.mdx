## Reporting Bugs

This guide walks you through submitting a bug report for Mojaloop. Following these guidelines helps maintainers and the community understand your report, reproduce the behavior, and find related reports.

### Before Submitting a Bug Report

- **Search existing issues**: Search the [existing bugs list](https://github.com/mojaloop/project/labels/bug) to see if the problem has already been reported.
  - If an open issue exists, add a comment with your context instead of opening a duplicate.
  - *Note*: If you find a closed issue that matches what you are experiencing, open a new issue and include a link to the original closed issue.
- **Check the FAQ**: Consult the [FAQ](https://github.com/mojaloop/documentation/blob/master/docs/getting-started/faqs.md) in the Wiki for a list of common questions and solutions.
- **Ask in Slack**: Join the Mojaloop Slack `#general` channel to ask questions or discuss behavior with other developers.

### How Do I Submit a (Good) Bug Report?

Bugs are tracked as [GitHub issues](https://github.com/mojaloop/project/issues).

Please capture all available information using the [Bug Report Template](https://github.com/mojaloop/project/issues/new?template=bug_report.md). Providing complete details helps maintainers reproduce, validate, and fix the issue quickly:

- **Steps to Reproduce**: Can you reliably reproduce the issue? If not, provide details about how often the problem happens and under which conditions.
- **Environment & Configuration**: Are you running locally or in AWS/cloud? What environment, chart/service version, and configuration are you using?
- **Diagnostics**: If the problem is related to performance or memory, include CPU profile captures, logs, or error stack traces with your report.
